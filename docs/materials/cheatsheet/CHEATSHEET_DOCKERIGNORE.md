`.dockerignore` лежит в корне контекста сборки и решает, какие файлы Docker вообще увидит. Это не оптимизация, а граница: то, что исключено здесь, не может попасть в образ ни через `COPY . .`, ни по ошибке. Файл один на контекст; вложенные `.dockerignore` не читаются. Как контекст участвует в сборке — в руководстве [Dockerfile: как устроен и как его писать](../guides/dockerfile_guide.md).

## Синтаксис

Комментарий — только отдельная строка, начинающаяся с `#`. Приписать пояснение в конец строки с шаблоном нельзя: оно станет частью шаблона, и правило перестанет работать.

```dockerignore
# Файлы .log в корне контекста
*.log
# Файлы .log на любом уровне вложенности
**/*.log
# Исключение из правила выше: этот файл в контекст попадёт
!app.log
# Каталог tmp на любом уровне
**/tmp
# Весь каталог dir/
dir/
# Только .txt прямо в dir/, без вложенных каталогов
dir/*.txt
```

!!! warning "Правило"
    В отличие от `.gitignore`, шаблон без `**/` действует только в корне контекста: `*.env` не исключит `config/prod.env`. Для секретов пишите `**/.env` и `**/*.env`. Порядок строк важен: побеждает последнее подходящее правило.

## Зачем нужен .dockerignore

`.dockerignore` уменьшает **build context** — набор файлов, который Docker передаёт
демону при сборке. Это влияет на:

- **Скорость сборки** — меньше данных передаётся демону
- **Размер образа** — лишние файлы не попадают в слои
- **Безопасность** — секреты (`.env`, ключи) не копируются в образ

## Проверка build context

Размер контекста виден в первых строках вывода сборки (`transferring context`). Состав контекста показывает одноразовая сборка, которая копирует его целиком и печатает список файлов, — так проверяют, что `.env` и `.git` действительно не уезжают к демону.

```bash
docker build --no-cache . 2>&1 | head -5     # Показывает размер build context

# Что именно попадает в контекст: Dockerfile читается из stdin, образ никуда не сохраняется
printf 'FROM busybox\nCOPY . /ctx\nRUN find /ctx -type f | sort | head -50\n' \
  | docker build --no-cache --progress=plain -f - .
```
