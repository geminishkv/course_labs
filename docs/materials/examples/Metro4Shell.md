В React Native Community CLI (Metro dev server) обнаружена критическая RCE‑уязвимость **CVE‑2025‑11953**, получившая название **Metro4Shell**. 
Она позволяет удалённо выполнять произвольные команды на машине разработчика через сетевой HTTP‑эндпоинт `/open-url`, причём **без аутентификации**, если Metro доступен извне.

RCE (Remote Code Execution) — это класс уязвимостей, при которых злоумышленник может удалённо выполнить произвольный код или команды на целевой системе через сеть, без физического доступа 
Как правило, RCE возникает из‑за ошибок в валидации ввода или небезопасных вызовов системных функций, когда приложение вместо штатной логики выполняет подменённую команду.

## Технический интро

Исследователи JFrog показали, что Metro dev server по умолчанию биндится на внешние интерфейсы (`0.0.0.0`) и поднимает HTTP‑эндпоинт `/open-url`.
Этот эндпоинт принимает параметр `url` из тела POST‑запроса и напрямую передаёт его в функцию `open()` из npm‑пакета `open` **без должной очистки и проверки**, что приводит к OS Command Injection.

Уязвимость затрагивает пакет **`@react-native-community/cli-server-api` версий с 4.8.0 до 20.0.0‑alpha.2**, который ставится вместе с `@react-native-community/cli` и используется стандартными командами `react-native run-android`, `run-ios`, `start`.
На Windows это даёт возможность выполнять произвольные shell‑команды с контролируемыми аргументами, на Linux/macOS — запуск произвольных бинарей, что в любом случае критично для dev‑машины.

**Ключевой момент:** достаточно запустить Metro dev server на машине разработчика и оставить его слушать не только `127.0.0.1`, но и внешний интерфейс — и он становится удалённо эксплуатируемым.

## Как злоумышленники эксплуатируют Metro4Shell

- Автоматизированные сканы `masscan`/`nmap` и поисковые сервисы (например, Shodan) ищут открытые Metro‑серверы, обычно по порту **8081** и характерным HTTP‑ответам.
- Проверяется наличие эндпоинта `/open-url` и возможность отправки POST‑запроса.

### Эксплуатация

1. Атакующий отправляет **crafted POST** на `/open-url` с параметром, содержащим вредоносный `url`, который на деле является командой ОС (например, PowerShell‑строкой).
2. На Windows типичный payload — Base64‑кодированный `powershell -EncodedCommand ...`, передаваемый через `cmd.exe`.

По данным VulnCheck и других исследователей, цепочка включает:
* отключение или ослабление Microsoft Defender (добавление исключений, изменение настроек);
* установку исходящего TCP‑соединения с C2‑сервером (например, `8.218.43.248:60124`);
* загрузку Rust‑бинаря во временный каталог и его запуск.

**Результат**: злоумышленник получает устойчивый удалённый доступ (RCE + возможная закреплённость в системе) и может выполнять произвольные операции на dev‑машине.

## Риски и возможные последствия

- **Полный RCE в контексте пользователя**, запустившего Metro: установка/удаление ПО, исполнение команд, работа с файлами и процессами.
- **Доступ к исходному коду и конфигурациям** проектов: `.env`, токены облаков, VPN‑конфигурации, SSH‑ключи, параметры CI/CD, доступ к приватным репозиториям.
- Использование dev‑тачек как **pivot‑точек для lateral movement** в корпоративной сети: подключение к внутренним ресурсам, атаке на CI/CD, облачную инфраструктуру, реестры контейнеров и т.д.

По аналогии с тем, как группировки вроде Vice Society или кампании с Magniber использовали PrintNightmare для распространения вымогателей, Metro4Shell может стать стартовой точкой для:
- шифрования ресурсов (ransomware);  
- кражи секретов и последующей продажи доступа (Initial Access Broker);  
- атаки на цепочку поставки (supply‑chain) через подмену кода/зависимостей.

## Типовой сценарий атаки шаг за шагом

1. **Рекогносцировка**  
   - массовое сканирование интернет‑диапазонов на TCP‑порт **8081** и проверка баннера Metro/наличия `/open-url`
2. **Первая стадия эксплуатации**
   - отправка POST‑запроса на `/open-url` с Base64 PowerShell‑payload’ом;
   - выполнение PowerShell, который:
     - добавляет исключения в Microsoft Defender
     - устанавливает TCP‑канал к C2
     - скачивает Rust‑бинарь
3. **Вторая стадия (Rust‑payload)
   - запуск UPX‑упакованного Rust‑бинаря
   - попытка закрепления (планировщик задач/служба)
   - сбор информации о системе и пользователе
   - поддержание скрытого C2‑канала для дальнейших действий.

## Меры снижения риска

### 1. Патчи и управление версиями

- Обновить `@react-native-community/cli-server-api` и связанный `@react-native-community/cli` до версий, где уязвимость исправлена (рекомендуется 20.0.0 и выше по данным JFrog/NVD).
- Регулярно проверять lock‑файлы (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`) на предмет подтягивания уязвимых версий зависимостей.

### 2. Сетевое ограничение Metro dev server

- Биндить Metro dev server **только на `127.0.0.1`**, а не на `0.0.0.0`, исключив внешнюю доступность.
- Ограничить доступ к порту 8081 фаерволом: разрешить только локальный доступ или трафик с доверенных хостов (эмуляторы, локальные прокси).
- Запретить запуск Metro на хостах, доступных напрямую из интернета, а также на общих (shared) серверах.

### 3. Мониторинг и детектирование

- Включить мониторинг HTTP‑запросов к `/open-url` (особенно POST) на Metro‑серверах: аномальные запросы, внешние IP, подозрительные параметры.
- Отслеживать запуск PowerShell с Base64‑аргументами (`-EncodedCommand`) и попытки изменения настроек Microsoft Defender.
- Контролировать исходящие соединения разработческих машин к подозрительным хостам и портам (например, `8.218.43.248:60124`) и блокировать их на уровне прокси/фаервола.
- Периодически проверять временные каталоги, задачи планировщика, службы и автозагрузку на предмет неизвестных UPX‑упакованных Rust‑бинарей.

### 4. Управление секретами и привилегиями

- Регулярно **обновлять секреты**, которые могли быть доступны с dev‑машины: токены облаков, ключи CI/CD, SSH‑ключи, VPN‑учётки.
- Минимизировать права локальных учётных записей разработчиков:
  - использовать отдельные учётки/токены для особо привилегированных операций (административные действия, доступ к прод‑ресурсам);
  - реализовать принцип Segregation of Duties (разделение ролей).
- Не хранить чувствительные данные в `.env` и других файлах в открытом виде без использования менеджера секретов.

## Сноска про порт 8081

**Порт 8081** — широко используемый **альтернативный HTTP‑порт** для веб‑сервисов, dev‑серверов и панелей администрирования.
Он использует TCP и обслуживает обычный HTTP‑трафик, часто применяясь для:
- внутренних веб‑консолей и систем управления (CI/CD, security‑консоли, админки приложений);
- dev/test‑серверов и вспомогательных сервисов, когда порт 80 уже занят или не должен светиться наружу.

Именно поэтому любые открытые 8081‑порты стоит рассматривать как потенциально высокорисковые точки входа и защищать их патчами, аутентификацией и сетевыми ограничениями.
