**9.** Checkov сканирует `docker-compose.yml` и выдаёт предупреждение `CKV_DOCKER_2: Ensure that containers do not run as privileged`. Разработчик отключает проверку через `# checkov:skip=CKV_DOCKER_2`. Что принципиально не так с таким подходом?

- A) Команда `skip` имеет неверный синтаксис — Checkov её не поймёт
- B) Пропуск проверки не влияет на реальную безопасность — это только предупреждение
- C) Замалчивание предупреждения не устраняет уязвимость: контейнер всё равно запущен с `--privileged`, CI будет зелёным, но риск побега из изоляции остаётся — это ложное ощущение безопасности
- D) Checkov — инструмент только для Terraform, в Docker Compose он неприменим

**10.** Какие из следующих настроек в `sshd_config` наиболее критичны для hardening SSH-сервера на production-хосте?

- A) Увеличить `MaxSessions` до 100 и отключить `TCPKeepAlive`
- B) Установить `PermitRootLogin no`, `PasswordAuthentication no`, `AllowUsers`, ограничить `MaxAuthTries`
- C) Сменить порт на нестандартный — это достаточная мера безопасности
- D) Включить `X11Forwarding yes` и `AllowAgentForwarding yes` для удобства администрирования
